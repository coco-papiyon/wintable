# github-issue-verify

## 入力と開始条件

GitHub CLI（gh）がインストール・認証済みであることを前提とする。GitHub操作は通常のghコマンドを使い、不足する操作はgh apiで行う。MCPとチャットのGitHubアプリ連携は使用しない。開始時の認証・対象確認とアクセス拒否時の承認付き実行は共通ルールに従う。

入力はIssue番号。対象リポジトリと組み合わせて解釈する。必要な入力がない、または対象が一意でない場合は確認する。

実行前に[共通ルール](references/workflow-rules.md)を必ず読み、Agent・機能・権限の確認、排他的ラベル更新、回数管理と再実行、要件判定を適用する。報告時は同ファイルの投稿テンプレートを使う。

実行依頼は以下に明記した投稿・ラベル変更・push等の許可として扱う。ユーザーが範囲を限定した場合は従い、環境の権限・承認要件は維持する。

## 作業前の必須手順

[共通ルールの「作業前の最新ソース取得」](references/workflow-rules.md#作業前の最新ソース取得全スキル必須)を実施する。対象remoteをfetchし、最新の対象ブランチと比較先のSHAを確認する。変更作業では作業ツリーも同期し、読み取り専用なら取得したSHAのソースを使う。未コミット変更や未pushコミットは保護する。取得・同期を完了してから以下の手順へ進み、最新取得に失敗したまま古いソースで続行しない。

コメント・ラベルの更新先は対象Issueのみ。計画はIssue本文を更新し、検証OK時のPR作成・本文設定は行う。PRへの報告コメントやラベル設定はしない。

## 手順

通常の「チェックして」「確認して」は、このスキル全体の実行依頼として扱う。ユーザーが明示的に「報告のみ」「ラベルを変更しない」「PRを作成しない」等と限定した場合だけ外部更新を省略し、報告に省略理由を記載する。設計資料が成果物の場合も、要件を満たしてOKと判定したなら同じ後続処理を実行する。

1. Issue本文と全コメントを読み、要件一覧を作る。
2. リモートの `feature/issue_#<Issue番号>` を取得し、既定ブランチとの差分と実装全体を検証する。既存PRがあればそのbaseを基準にする。
3. 要件別の根拠と判定、全体のOK/NG、検証したSHAをIssueコメントへ投稿する。
4. 全体OKならIssueを `status:implemented` にし、対象ブランチからPRを作成する。同じhead/baseのPRが存在する場合は再利用する。
5. PR本文には目的、変更内容、要件への対応、検証結果、Issueと検証コメントへのリンクを含め、独立した行に `Closes #<Issue番号>` を必ず記載する。別リポジトリのIssueの場合は `Closes <owner>/<repo>#<Issue番号>` とする。既存PRを再利用する場合も、対象Issueのクローズ指定がなければ追記する。
6. 全体NGならIssueを `status:changes-requested-n` にし、修正箇所または不足する検証を具体的に示す。新しいPRは作成しない。

PR作成に失敗した場合は検証OKと作成失敗を分けて報告し、再実行時に重複作成しない。

## 終了前の必須確認

判定をチャットへ返すだけでは完了ではない。最終報告の前に次の状態をリモートから再取得して確認する。

- 検証結果のIssueコメントが存在し、要件別判定、全体OK/NG、検証SHAと根拠を含み、コメントURLを取得できる。
- OKの場合、Issueに `status:implemented` があり、他のステータスラベルがない。対象head/baseのopen PRが存在し、PR本文に正しい `Closes` 指定があり、PR URLを取得できる。
- NGの場合、Issueに正しい回数の `status:changes-requested-n` があり、他のステータスラベルがない。新しいPRを作成していない。
- 操作失敗の場合は、利用可能な他の連携・CLI・APIで同じ操作を実行できるか確認する。成功した操作は繰り返さない。実行不能なら完了扱いにせず、未完了操作と実際のエラー・不足権限を明記する。

最終報告には「検証判定」「結果コメントURL」「更新後のステータス」「PR URL（NGなら作成なし）」「未完了操作」を必ず示す。結果コメント内の次の操作も、実際のPR URLやラベル更新結果に合わせて更新する。OK判定だけを理由に完了と報告しない。

## 完了と途中失敗

最終報告は作業内容が分かるレベル1見出しで始め、対象URL、操作結果、コメントURL、該当するブランチ・SHA・ラベル、検証結果、実行Agentと実行方法を記載する。

外部操作の成功は再取得して確認する。途中失敗は完了と未完了を区別し、同じ操作を無制限に再試行しない。対象不一致、権限不足、未解決の競合などで続行できない場合は原因と必要な対応を報告する。再実行は既存記録とリモート状態から未完了部分だけ再開する。
