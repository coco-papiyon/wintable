## 後続実装の環境

- 制御側: Windows 11 amd64とWindows Server 2022 amd64、固定Goツールチェーン。
- 対象: 同OSの隔離VM各1台、OpenSSH Server、cmd既定シェル、PowerShell 5.1以上、公開鍵認証。
- 正常鍵、未知鍵、変更鍵、誤認証鍵、暗号化鍵を準備。ネットワーク断と遅延を再現可能にする。

## 実装の分割と完了条件

1. Goプロジェクト/CLI: go.mod、フラグ、context、結果型を作る。help・無効引数・終了コードが単体で通る。
2. 入力解析（1に依存）: config/inventory、例ファイル、全件事前検証を作る。V-01〜03、V-15/17の接続前検査合格。
3. engine/SSH（1・2に依存）: 模擬Sessionで並列・中断を固め、鍵検証付きSSHへ接続する。V-04〜06、V-18の転送・期限検証合格。
4. モジュール（3に依存）: 固定PowerShellラッパー、commandとfile_contentを作る。V-07〜11、V-14〜18のモジュール・実機項目合格。
5. Windows実機/配布（全工程に依存）: 対象OS試験、集計・導入、依存監査、ZIPを作る。V-12〜13と全回帰合格。

I-01で初期仕様を採用済み。工程1ではGo 1.27.3でCLI単体テスト、vet、Windows amd64ビルドとhelpのスモーク確認を行う。help経路、必須引数、9フラグと既定値、forks=0/1/64/65、timeout<=0、型不正、未知フラグ・非対応指定、余剰引数はCLI試験に含める。不正入力は終了2・Executor呼出0回。有効runは注入Executorで解析値とcontext/cancel伝播を検証し、実バイナリの暫定動作は終了3とする。nullable changed/exit_codeと通信・プロセス結果の分離も基盤試験に含める。

V-01のうちJSON内容検証とV-02以降の実行動作は後続工程。サイズ上限の採用はサイズ検査の実装完了を意味しない。実機接続の成功は主張せず、V-05〜18のWindows実測は未確認として残す。未確定の認証方式や互換範囲は設計書の一覧を引き継ぐ。

I-04単体検証: internal/result/report_test.goでV-12の全status、ホスト/全体件数、安定順、単一JSON文書、null/false/0、空配列、無効内部結果、終了値の全組合せ、失敗/短い書込み、出力中キャンセルを検査する。
V-11出力単体では0、1MiB−1/同値/+1、5MiBの任意バイトをCaptureへ流し、全量消費・保持上限・base64往復・既定本文除去・エラー秘密非出力を確認する。既存本文の描画時上限制限も検査する。
CLIは診断/help障害、キャンセル優先、ResultExecutorのJSON/テキスト出力を確認する。実SSHの並行排出・Ctrl+C接続解放・Windows実機項目は後続Issueで未確認。
I-03ではV-02/03/15/17の単体検査、V-16の合成最終行検査を追加。content/JSON/CRT/ラッパーの同値と±1、非BMP、CRT引用符・末尾バックスラッシュ、最後のホスト・タスクの不正による部分計画非返却とCLI Executor呼出0回、送信バイト列の所有権を検査する。実ラッパー、OpenSSH/cmd接頭辞、対象exeのargv往復と両対象OSの実測は後続Issueで未確認。
